# Cultivator 素材复盘：AI 生图约束 · 逐帧动画 · FX 分层的经验

本页是**经验/踩坑复盘**（讲「为什么」与「怎么想」）。确定值 / 尺寸 / 对外规范的「标准」见
[`cultivator-asset-standard.md`](./cultivator-asset-standard.md)，操作细节与 checklist 见
[`cultivator-asset-pipeline.md`](./cultivator-asset-pipeline.md)。功德修行主题的角色（凡人→修行者→
小和尚→罗汉→菩萨→佛祖）全部走 **AI 生图 → 切分 → 去底 → SVG 嵌入 + CSS 动画**，这套流程反复
翻车又收敛，下面是提炼出的可迁移经验。

---

## 0. 一句话总纲

**角色本体交给 AI 生图（可控性差但美术上限高），运动与特效交给代码（可控、可复用、可缩放）。
两者的边界一旦划错，就会同时丢掉「稳定」和「好看」。**

---

## 1. AI 生图：约束比措辞更重要

### 1.1 约束要写成「可证伪的硬指标」，不是形容词
- 有效：「6 个等宽全身面板」「身体头顶→坐底在每帧同像素」「木鱼钉死在同一 (x,y)」「观者左侧、
  6 帧不翻转」。这些能一眼判过/不过。
- 无效：「保持一致」「精致」「协调」——模型会用自己的理解自由发挥，产出漂移。
- 经验：**每条约束都要能对应一条验收动作**（叠图重合？基线相等？道具同侧？），否则等于没写。

### 1.2 正向描述 + 显式 FORBIDDEN 双管齐下
- 只说「画干净的角色」不够；必须列 `FORBIDDEN`：光环 / 佛光 / 背光 / 祥云 / 莲瓣 / 火花 / 蜡烛 /
  钟 / 侧道具……AI 特别爱「贴心地」加背景光效，不禁就会烤进图。
- `scripts/generate-cultivator-ai-assets.js` 里把 `REF_STYLE` / `FORBIDDEN_FX*` /
  `STAGE_PROMPTS` / `KNOCK_FRAME_SEQUENCE` 作为**唯一约束真相源**，改约束只改这里并同步文档。

### 1.3 参考图 = 最强的一致性锚
- 双参考图（当前阶段 `idle` + `chibi-monk-reference` 风格图）比任何文字都稳。
- 生 working sheet 时把「**复制这张 idle 六次，只动手臂**」作为 CORE TASK，胜过描述六个姿势。
- 形象要「换气质」（如佛祖要华丽/如来相）时，直接喂一张**目标参考图**（`reference/buddha-ornate-reference.png`），
  比堆一串形容词有效得多。

### 1.4 对抗随机性：多候选 + 择优 + 重生，不要修图
- 同一 prompt 多跑几次挑最好的；不过关就**重生**。
- **修图（lock/composite/局部贴）是主路径的反面教材**：`lock-cultivator-working-to-idle.js` /
  `composite-cultivator-knock-on-idle.js` 都会切脸、鬼影、道具像素对不齐，已废弃。
- 心智模型：AI 生图是「抽卡」，工程要做的是**把合格线量化 + 便宜地重抽**，而不是给废卡描边。

### 1.5 身份道具 vs 特效：谁烤进图，谁留给代码
- **能定义「这是谁」的结构件**（佛祖的莲花台、华丽袈裟、mandorla 光环）**烤进角色图**——它们必须与
  角色像素级绑定，代码画不出这种美术密度。
- **运动/氛围特效**（呼吸、敲击反馈、祥云绽放、软光晕外扩、莲瓣飘落）**留给代码**——要动、要按阶段
  变强、要可复用。
- 反面案例：早期把光环/祥云烤进 idle，但 working 帧没有 → **状态切换时光环忽有忽无**，而且污染了
  切分用的身体高度锚（见 §2）。教训：**同一元素要么在所有状态都在，要么都不在。**

### 1.6 透明底是「必查项」，AI 给的透明经常是假的
- AI 输出的「透明背景」经常是**把灰白棋盘格 / 纯色底烤进像素**（`cloud-scrolls.png` 就整张 0 透明像素）。
- 复杂描边（佛祖光环的放射线缝）之间会残留**近黑不透明像素**，视觉上像有黑底。
- 处置：`make-cultivator-pngs-transparent.js` 不只做角点 chroma-key，还要
  **从边界 flood 清理近黑缝隙 + 淡雾描边**；上线前用**浅底/深底两种背景**离屏截图核对，别只看一种。

## 2. 逐帧动画：大小一致是第一命题

这是本需求翻车最多、最反直觉的一块。

### 2.1 「一大一小」的真正根因是**归一化的锚点错了**
- 症状：静态正常，敲木鱼时角色忽大忽小。
- 错误做法：切分时按**含举起木槌的整框 bbox** 缩放——举槌帧整框更高更宽，归一后把身体缩小。
- 正确做法：**以身体高度（头顶→坐底，`bodyMetrics`）为锚**，木槌只是往上顶进透明 padding，不参与缩放。

### 2.2 六帧共用**一个**缩放系数，切忌逐帧各自缩放
- 原图 6 格本就同一比例；逐帧各自算缩放，只会因举槌帧的头顶/手臂**误检测**把本来一致的图缩成一大一小。
- 做法：取 6 帧身体高度的**中位数**（对个别坏帧鲁棒）→ 只算一次系数对齐 idle，全帧套用。

### 2.3 锚图（idle）必须先去背，否则基线全错
- 切分用 `loadIdleAnchor` 读 `candidates/{stage}-idle.png` 求 `bottomY`。
- 若该 idle **没 chroma-key**，`contentBBox` = 整张画布，`bottomY≈1023` → working 被整体放大并贴到画布底。
- 教训：**新 idle 落地，candidates 与 generated 两份都要跑去背**，再切分。

### 2.4 验收要用**独立度量**，别让切分脚本自证自洽
- 用 split 内部同一套 `bodyMetrics` 去验收，会永远显示 `ratio≈1.0` 骗过自己。
- 独立指标：切分后各帧内容框 `bottomY` **全等**（基线锁死），`contentH` 差异**只来自木槌高低**、不来自身体。

### 2.5 CSS 逐帧播放：用 linear + 硬 opacity 切
- 6 帧堆叠，靠关键帧在整点百分比**硬切 opacity**（`0/16.67/…/100%`）。
- 不要用 `step-end`：尾帧百分比处理不好会出**空帧 / 末帧闪烁**，看起来像「播放坏了」。
- Cursor 内置查看器**不渲染 SVG 动画**；「看起来坏了」先分清是 **CSS 播放** 还是 **图本身漂移**——
  用浏览器 preview / 离屏冻帧区分。

### 2.6 不是所有阶段都适合逐帧
- 佛祖后来改成**不敲木鱼**：working 直接复用 idle 打坐图 + 代码 FX（`wrapNoKnockWorkingSvg`），
  无 6 帧 sheet。**能用「一张图 + 代码运动」表达的状态，就别硬凑逐帧**——省素材、免漂移、免体积。

## 3. FX 分层：用对工具，别用错介质

### 3.1 每种 FX 选**最合适的介质**
- **软光晕 / 佛光**：SVG `radialGradient` 程序化画——清晰、可无限缩放、零素材、易做呼吸/外扩。
  （AI 生一个模糊光斑既糊又占体积。）
- **祥云卷纹**：手写 SVG 线条太寒酸 → 换成**一张 AI 生成的金色如意云卷环**（透明底+透明中心），
  代码只负责让它绽放/环转。美术上限交给 AI，运动交给 CSS。
- **细碎粒子 / 莲瓣**：程序化小图元 + CSS 关键帧即可。

### 3.2 「看不见」往往是**强度问题**，不是逻辑问题
- 早期祥云是发丝细线、佛光不透明度 ~0.3，桌宠尺寸下**几乎不可见**，用户直接判「没效果」。
- 教训：**桌宠是小尺寸远观**，FX 的不透明度/半径/线宽都要按「缩到 64–128px 还看得出」来调，
  在大图上「刚刚好」= 桌面上「等于没有」。上线前务必在**目标尺寸**下核对。

### 3.3 可复用素材要控体积
- AI 云环 1024² base64 内嵌进多张 working SVG 会让体积暴涨。
- 做法：**降采样到 ~384²** 再嵌，单张 working SVG 增量 ≲0.3MB。

### 3.4 强度**随阶段单调递增**，集中在一张表里
- `KNOCK_FX_TIER` 一张表驱动全部阶段的云/光/莲瓣/峰值；改 FX 只改这张表，天然保证
  「境界越高越盛大」的单调性，不散落在各处。

### 3.5 常驻气场 vs 事件爆发要分清
- **常驻**（佛光呼吸、祥云环转）在 idle+working 用**相同 CSS**，状态切换不闪跳。
- **事件爆发**（敲中绽放、莲瓣飞散）只在 working。
- 一旦把「常驻」做成「仅 working」，状态切换就会突兀跳变。

## 4. 工作流与验证的经验

- **离屏冻帧自查**最省事：本地 http server 打开 working SVG，
  `document.getAnimations().forEach(a=>{a.currentTime=756;a.pause()})` 冻到绽放峰值截图，
  离屏就能核对 FX 是否读得出，不依赖真机录屏。
- **浅底 + 深底两种背景**都要看，才能同时抓到「假透明白底」和「近黑残留」。
- **Cursor 看不了 SVG**：验收一律走浏览器 preview HTML / 冻帧截图。
- **桌宠进程会写回 prefs**：手改 `clawd-prefs.json` 调境界前先**完全退出 Clawd**，否则一启动被写回；
  调试优先用 Settings Theme 页的 stage select +「敲木鱼」按钮，别依赖 `debugStageId`。
- **临时/调试产物集中在 `candidates/`**，验收通过才拷 `generated/`；`candidates/` 长期只留各阶段
  `{stage}-idle.png` 锚点，raw/overlay/preview 用完即清（曾堆到 128MB）。

## 5. 可迁移的通用原则

1. **重生 > 修图**：生成式素材当「抽卡」，把合格线量化 + 便宜重抽，别给废卡描边。
2. **约束可证伪**：每条 prompt 约束都对应一条验收动作。
3. **划清 AI/代码边界**：身份结构烤进图，运动氛围留给代码；同一元素在各状态要么都在要么都不在。
4. **锚点思维**：一致性来自「锁定一个稳定锚」（身体高度 / 坐底基线 / idle 参考图），不是逐个体调。
5. **目标尺寸验收**：小尺寸远观的东西，必须在最终尺寸下判「看不看得见」。
6. **单一真相源**：约束集中在 `STAGE_PROMPTS` 等常量、FX 集中在 `KNOCK_FX_TIER`，改一处、同步文档。
7. **透明底默认不可信**：AI 的「透明」经常是假的，去背 + 双背景核对是必查项。
